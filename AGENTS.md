# Project rules

- Normalize character uploads and host references to PNG with the shared browser converter before storage; validate PNG signatures before masked decoding so JPEG/WebP inputs cannot reach the PNG-only decoder.

- Every Studio shot needs both a start and an end frame (HTTPS only, enforced in the client and the shared studio-clip/contract.ts schema), because shots render independently between keyframes; chaining reuses a shot's end as the next start with no render wait. Primary is the default; StudioClipPanel auto-resubmits the identical 9-field payload (same seed) to backup only when primary fails or is unavailable, because backup has one worker. Shots hold multiple takes that are never overwritten; approving sets the active take used for stitching and re-anchors the next unapproved shot; started-but-failed jobs are kept as video-less takes so their cost is counted. Cost = worker execution seconds × one editable pool rate. Keep validation, QC and cost math in studioClipUtils so it is testable without GPU jobs.
- Studio clips use the existing rehost-video service before playback; keep the source on saving failure and isolate playback recovery in StudioClipPlayer so storage outages never discard completed shots.
- Studio shots and final sequences live in persisted ProjectContext so switching to Music does not discard shots; stitch through the dedicated studio-stitch function with a fixed endpoint and route/params envelope, keeping worker credentials server-side and final playback on StudioClipPlayer.

- The Director workspace uses dedicated Script, Storyboard, Director and Sequence routes under one persistent Dashboard/ProjectProvider; editable drafts belong in ProjectContext, and visited tools remain mounted to preserve in-flight work during navigation.
- Sequence UI lives in StudioSequencePanel, with optional music on the Sequence page; StudioClipPanel can embed it for regression coverage, and final sequence records retain their worker job ID for traceability.
- Keep the compound-interest proof server-authorized and Shotstack sandbox-only; derive visuals and audio trims from one saved-word timeline and world-space foot anchors so caption, chart and gait timing remain testable without rendering.
- Keep illustration proofs in studio-render as sandbox-only formats with separate cached narration and pure word-timed plans, so new reviews cannot overwrite compound-interest assets or bypass server authorization.
- Keep cartoon host artwork in studio-render/host.ts with the existing joint IDs and segment lengths, so visual redesigns preserve word-timed gestures and planted-foot motion.
- Keep the replaceable Daniel character record, layered parts, pure named performance and room separate under studio-render/design; danielAnimation supplies identical seekable assets to local preview and the authorized daniel-proof sandbox format, with mouth motion derived from cached audio loudness.
- Keep image-animation attempts in server-owned records with globally unique request IDs, private owner-scoped inputs, verified Replicate completion webhooks, and deterministic video paths; uncertain submissions never create another prediction and save retries only recover the existing output.
- Build film submissions through the pure filmAnimationRequest helper; legacy continuation requires extracted frame_path, while automatically reviewed shared-boundary shots use one end/start asset plus identical scene state and camera so eligible jobs can overlap without a render wait.
- Expose capscify/extract-frame as a non-generation gateway utility and reverse the decoded tail before selecting one frame; otherwise an earlier near-end pose is mistaken for the actual final frame.
- Character film links may select an owner-scoped saved film with the film query parameter; direct review links must not silently open a newer draft.
- Both bulk and per-shot storyboard generation use drawFrame's single-moment, single-character constraints to prevent before/after collages from becoming animation inputs.
- Keep automatic film preparation as bounded server-owned ticks with saved scene/event records, operation intent, request allowances and frame-review results; preserve uncertain requests without automatic resubmission and authorize video only after every required frame review passes.
- After two camera/location corrections, replan unstarted actions once against the actual opening within the existing allowance; save edit provenance and review history, use localized PNG masks when available, and retain exact shared-boundary assets so recovery cannot invent a new opening or duplicate charges.
- Background explainer exports expose only owner-scoped reads and input-column inserts to authenticated users; only the service role may claim or update exports, because clients must not control ownership, leases, or completion.
- The external explainer worker talks only to the explainer-bridge function with a shared bearer token; the bridge enforces live leases and job-scoped storage paths, because the service-role key must never leave the backend.
- Whiteboard sampling returns BoardStroke records with points and average source-ink color; reveal rendering consumes those records so colored artwork survives export.

- New automatic explainers use independent single-opening-image shots with deliberate cuts and opening-frame safety review; preserve paired/shared contracts for existing continuous drafts so cut films avoid pixel-matched ending edits without bypassing identity checks.
