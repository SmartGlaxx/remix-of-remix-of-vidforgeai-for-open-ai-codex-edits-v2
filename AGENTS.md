# Project rules

- Studio clip chaining is explicit; first-frame conditioning is verified on both engines, so either may render chained shots. Primary is the default; StudioClipPanel auto-resubmits a shot with identical inputs (including a fixed per-shot seed) to backup only when the primary fails or is unavailable, one shot at a time, recording the failed primary job/error and backup job on the clip, because backup has a single worker and must not take ordinary traffic. Keep URL/warning validation in studioClipUtils so the flow is testable without GPU jobs.
- Studio clips use the existing rehost-video service before playback; keep the source on saving failure and isolate playback recovery in StudioClipPlayer so storage outages never discard completed shots.
- Studio shots and final sequences live in persisted ProjectContext so switching to Music does not discard shots; stitch through the dedicated studio-stitch function with a fixed endpoint and route/params envelope, keeping worker credentials server-side and final playback on StudioClipPlayer.
